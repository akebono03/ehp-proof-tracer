# Phase 171 R2J-R4-R9-R3 — Hopf 全射性の最初の停止点の監査

## 対象

R4-R8 で完成した $\pi_6^3=\mathbb Z/4\{\nu'\}$ の証明木を、R4-R9-R2 の限定 Provider で共通再帰探索したところ `partial` となった。登録済み `audit.json` が示す最初の未解決前提は

$$
H:\pi_7^3\longrightarrow\pi_7^5\quad\text{の全射性}
$$

である。これに依存する $\Delta=0$、$E$ の単射性、短完全列、位数4は連鎖して未完成となる。

## 変更対象と追加位置

リポジトリ直下に **新規** `phase171_r2j_r4_r9_r3_hopf_frontier_diagnostic/` を追加する。

- `audit.py`：`_git`、`_hopf_goal`、`_unique_hopf_node`、`_proof_event`、`_failure_class`、`inspect_first_hopf_frontier`、`main` を新規追加。内部の `observe` と `trace_match` は監査中だけの計測関数。
- `tests/test_audit.py`：新規8テストを追加。既存 R4-R9-R2 のテスト7件も限定実行する。
- `__init__.py`、`tests/__init__.py`、`run.ps1`、`README.md`、`CODE_FULL_JA.md`、`監査仕様.md`：新規ファイル。

既存本番ファイル・テスト・ドキュメントは変更しない。import の変更はない。

## 監査方法

1. `develop` にある現行コードから出典で選別した $\pi_6^3$ の引用境界を取得する。
2. R4-R8 の実際の `ProofStep` から $H:\pi_7^3\to\pi_7^5$ の `INFERENCE` を一意に特定し、両前提の型と推論状態を記録する。
3. R4-R9-R2 の `inference_expansion_catalog` と `scoped_expansion_provider` を変更せず利用する。
4. 元の $\pi_6^3$ の目標を `reconstruct_registered_goal` で実際に探索する。`progress_observer` と局所的な `unittest.mock.patch.object` により、元の matcher 呼出しと結果を監視する。matcher の戻り値は加工しない。
5. 入力された証明ステップの `GIVEN`／`INFERENCE`、対応した Rule、未解決 Goal、前提が揃わなかったか matcher が拒否したかを `output/audit.json` に記録する。
6. 既存追跡ファイルの状態が変わっていないことを確認する。

## 完了条件

限定 pytest が PASS し、`PHASE171_R2J_R4_R9_R3_RESULT=PASS_AUDIT_ONLY`、`NEW_GIVEN=0` を確認する。監査の成功は共通探索や Web 完成を意味しない。

R4-R9-R4 以降の最小修正候補を決めるための証跡を出す段階にとどめる。未証明の `ProofStep` の注入、DB 目標の `GIVEN` 化、Trust Boundary の省略、Web 完成状態の偽装は行わない。Phase 終了前の全体 pytest も行わない。
