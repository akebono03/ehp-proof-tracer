# Phase 169 R10E4 — 先行 DB 結果の採用

## 選択順序

証明対象 $(n,k)$ に対して、DB の先行結果 $(n',k')$ は

$$
k'<k\quad\text{または}\quad (k'=k\text{ かつ }n'<n)
$$

の場合にだけ、既知の DB 前提として採用できる。この辞書式順序は Toda 原典の掲載順序とは別の、プロジェクトで明示的に採用した結果利用順序である。

## データと証明の区別

DB は `sphere.csv` の直接の $(n',k')$ 行から型付き群構造を構築する。`SphereRepository` による安定範囲の補完結果は、独立の先行 DB 前提とは認定しない。

採用した DB 結果は Proof Tree で `GIVEN` を構成するが、その `note` と Reference locator には `ADOPTED_DATABASE_PRIOR` と `DB prior: sphere.csv` を記録する。これは文献命題の `FIXED_STATEMENT` ではない。文献命題番号は、別途一致が確認された場合に参考表示するだけで、採用の条件には使わない。

Trust Boundary は ProofStep の表示名・注記だけを信頼しない。群次元とステム、元の DB 行の存在、型付き群構造の完全一致、証明対象との厳密な先行関係を毎回検査する。登録済み文献命題には元から存在する publication precedence の検証を引き続き適用する。

## 共通の安定基点

各ステム $k$ で基点が `sphere.csv` に明示的に収録されていれば、$n>k+2$ に対し

$$
E^{n-k-2}:\pi_{2k+2}^{k+2}\xrightarrow{\cong}\pi_{n+k}^n
$$

を用いた共通群構造輸送が可能になる。生成元の像は別の型付き証明を必要とする。基点 $n=k+2$ 自身は、この輸送では導出できない。

## 範囲

今回の変更は既存 `R10E1/R10E2` の共通検索器に DB の先行前提を接続する。新しい系列別の規則、登録命題の大量追加、未検証 DB 値の Toda 文献への偽装は行わない。

全体 pytest は Phase 169 の終了時に限る。
