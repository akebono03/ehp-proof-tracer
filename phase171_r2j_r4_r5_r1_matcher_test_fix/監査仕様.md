# Phase 171 R2J-R4-R5-R1 — 前提照合テスト修正

## 失敗原因

`proof.py` の `_find_all_matching_premise_bindings()` は、渡された `available_steps` を `premise_patterns` に照らして探索し、照合された順序で `InferenceMatch.premises` を返す。そのため入力順だけを逆転しても `find_inference_matches_for_rule()` は正しく1件を返す。R4-R5 の旧テストは逆順の入力を拒否すると誤って期待していた。

## 変更ファイル・関数・追加位置

- `phase171_r2j_r4_r5_short_exact_sequence/tests/test_audit.py`：既存の `test_unrelated_sequence_or_reordered_premises_are_rejected()` を、同じ位置で `test_unrelated_sequence_is_rejected_and_reordered_premises_are_matched()` の全文に置換する。import 変更なし。
- `phase171_r2j_r4_r5_short_exact_sequence/CODE_FULL_JA.md`：既存コード（`source.py`、`audit.py`、テスト、`run.ps1`）を含む文書全体を修正後の内容に更新する。
- 新規 `phase171_r2j_r4_r5_r1_matcher_test_fix/install.py` の `_digest()`、`preflight()`、`main()`：SHA-256 を比較し、想定外のローカル編集があれば中止する。新規ファイル全体は `CODE_FULL_JA.md` に収録。
- 新規 `run.ps1`、`README.md`、`監査仕様.md`、`CODE_FULL_JA.md` および `assets/` の全文ファイル。

## 検証事項

1. 同じ型付き3前提を逆順に渡しても照合器が1件に正規化し、原来の順序の証明木を作る。
2. 不正な E の終域（`TodaPrimaryGroup(6,4)`）への差し替えでは照合は0件になる。
3. 無関係な短完全列の `GoalExpansion` は認めない。
4. 既存の数学的規則と引用・出典を変更しない。
5. 限定 pytest は既存の27件のみ、全体 pytest は Phase 終了時に限定する。
