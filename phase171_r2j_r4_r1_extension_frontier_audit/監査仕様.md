# Phase 171 R2J-R4-R1 — 群拡大の未解決前提監査

今回の対象は $\pi_6^3\cong\mathbb Z/4\{\nu'\}$ の完成証明そのものではない。R2J-R3 までに確立した $\Delta=0$、$E$ の単射を確認し、残る群構造の前提を列挙する。

既存の R2J-R3 証明木を実際に再構成し、採用された固定文献命題と publication precedence（文献掲載順）によって選別された前提のみを確認する。Toda (5.3) の $2\nu'=\eta_3\circ\eta_4\circ\eta_5$ と $H(\nu')=\eta_5$、$\pi_5^2$・$\pi_6^5$ の登録済み目標、Proposition 4.2 の $E$–$H$ 窓を確認する。

$E(\eta_2^3)=\eta_3\circ\eta_4\circ\eta_5$ の候補は証明義務であり、監査だけで既知の等式にしない。$\pi_5^2$ の DB 行を `GIVEN` に昇格しない。対象の Proposition 5.6 の結論を前提として引用しない。未解決の全射性と群拡大を先取りしない。

変更対象：新規監査フォルダーの `audit.py`、`tests/test_audit.py`、`run.ps1`、文書のみ。既存クラス・関数・テスト・開発ドキュメントに変更なし。監査で生成する `output/audit.json` と `output/audit.md` は監査フォルダー内のみ。pytest は `-p no:cacheprovider` で実行し `.pytest_cache` の更新を防ぐ。

完了条件：R2J-R3 証明木の再構成に成功し、選別された出典の有無・型・検討候補を JSON に書き出し、追跡ファイル差分を変化させないこと。Phase 171 の全体 pytest は Phase 終了時のみ。

監査コードの型確認は既存 `_endpoints()` で三重合成を再帰的に検査する。$\pi_5^2$ の生成元は $\eta_2^3$ であり、単独の $\eta_2$ を代用しない。これは候補生成に対する検査であって、新しい ProofStep や GIVEN を作らない。
