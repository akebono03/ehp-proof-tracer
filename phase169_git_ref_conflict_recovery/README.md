# Git Reference Conflict Recovery (Phase 169 support)

This utility addresses two invalid duplicate Git ref files generated by a Dropbox synchronization conflict. It does not change application code, proof steps, tests, the actual `develop` branch, or the `origin/develop` branch. It does not run `git reset`, `git pull`, or `git fetch` automatically.

By default `run.ps1` is a dry-run inspection. Pause Dropbox synchronization for the repository before running the explicit `-Repair` operation, and close any other programs performing Git operations. The repair moves only invalid, Dropbox-conflicted copies named like `develop (computer の競合コピー YYYY-MM-DD)` from `.git/refs/heads/` or `.git/refs/remotes/origin/` into a timestamped directory in your Windows home directory. Original bytes are retained, with a SHA-256 manifest.

## Commands

Run from the repository root after extraction:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\phase169_git_ref_conflict_recovery\run.ps1"

powershell -NoProfile -ExecutionPolicy Bypass -File ".\phase169_git_ref_conflict_recovery\run.ps1" -Repair

git fetch origin develop
git status -sb
```

A missing normal `develop` or `origin/develop` reference aborts the repair. An unexpected valid reference name, unexpected number of conflicting files, or checksum mismatch also aborts the operation. Only the exact invalid ref-file patterns shown in the original log are eligible.

## Boundaries

No project code, tests, database, documentation, or Git commit is modified. The full pytest suite is not run. If `git fetch` still fails afterwards, do not run `git gc`, `git reset --hard`, or delete additional `.git` files; inspect the new error first.
