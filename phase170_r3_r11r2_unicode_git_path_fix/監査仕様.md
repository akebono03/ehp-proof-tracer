# Phase 170 R3-R11R2 — Git 日本語ファイル名対応の終了監査

## 原因

R3-R11R1 の事前検査は `git diff --name-status 08382968... HEAD --` の結果を、許可済み監査ディレクトリで始まるパスと比較した。Windows の Git は標準の `core.quotePath=true` に従い、`監査仕様.md` の UTF-8 バイト列を `\347\233...` 形式の八進数エスケープで二重引用した。そのため実際には許可済みの追加ファイルを、許可外の変更と誤判定した。

この失敗は **全体 pytest の結果を表さず**、従前の 33/33 Proof Search・Web 検証を無効化しない。前回の実行は事前検査で停止した。

## 変更対象・変更位置

- 新規ディレクトリ `phase170_r3_r11r2_unicode_git_path_fix/` をリポジトリ直下に追加する。
- `closeout.py` の既存関数 `preflight()` 内にある Git 差分呼び出し一箇所のみを修正し、関数全文を同梱する。
- `tests/test_contract.py` の既存テストでは、`preflight()` の Git コマンド引数に合わせて期待値を変更し、日本語パスの受理・許可外パスの拒否を追加する。テスト関数全文・import 全文を同梱する。
- `run.ps1` は新規パッケージの `closeout.py` を呼び出す。
- `README.md` は英語。本書および `FULL_CHANGED_CODE_JA.md` は日本語。

本体の探索規則、Toda (5.2)/(7.12) の登録、Trust Boundary、既存のファイル・テスト・正式文書5件は変更しない。

## 修正の意味

`git -c core.quotePath=false diff --name-status <監査 HEAD> HEAD --` を **そのコマンドだけに適用**する。ユーザーの Git 設定は書き換えない。差分行の `A`（新規追加）判定、2つの許可済みディレクトリの範囲、未審査 blob の拒否、HEAD 固定、33件の独立した監査結果と Web 検証の検査を維持する。

## 検証

- 既存契約テストと追加2件：ローカル `24 passed`。
- 追加した実 Git テスト：一時 Git リポジトリで `監査仕様.md` をコミットし、エスケープ有無を比較する。
- 変更対象外の日本語ファイル：`preflight()` は拒否を維持する。
- 正式な全体 pytest は通常実行でのみ行う。Phase 170 の終了に必要な実測結果はまだない。

`PHASE170_R3R11_DOMAIN_REPORT=VERIFIED_33_OF_33`、`PHASE170_R3R11_FULL_PYTEST_EXIT=0`、`PHASE170_R3R11_TRACKED_UNCHANGED=True`、`PHASE170_R3R11_RESULT=FULL_SUITE_PASS` が揃うこと。その後、別作業として正式な5文書の全文更新と Phase 170 終了記録を行う。
