# Phase 165 Renderer R5-R1 監査修正

## 問題の原因

旧 R5 の `project.rglob("*.py")` がバックアップ・過去のインストーラー・履歴ディレクトリを本番ソースとして数え、走査数 5,820・旧 import 608 件という過大集計になった。R4 自体がロールバックされたことを意味しない。

## 対象

- プロジェクト直下 `*.py`（本番モジュールと直下のテスト）。
- 正式な `tests/**/*.py`（回帰テスト）。
- 監査用パッケージ、復元バックアップ、歴史的フォルダーは対象外。歴史的フォルダーの旧 import 残存は、本番コードの依存残存とは別問題として扱う。

## 変更ファイル

新規 `phase165_renderer_r5_r1_scope_fix/audit.py`, `test_r5.py`, `run.ps1`, `README.md`, `AUDIT.md`, `CHANGED_CODE.md`。既存の Python モジュール・Renderer・テストは変更しない。

## 限定検証

監査テストは9関数中、純粋な監査ロジックの6件を独立実行して成功。残り3件（実システムの表示動作）は Windows 実行時に実施する。既存の `test_phase165_r56_common_renderer.py` も限定実行する。Phase 全体 pytest は実施しない。

## 完了条件・次の境界

静的チェックが PASS しても補助 Renderer の意味的重複は未判定。残りの補助関数と動的分岐の監査が必要なら R5 の残課題として報告し、無条件に「完全一本化」と宣言しない。証明探索の変更は次の作業であり R5-R1 は行わない。
