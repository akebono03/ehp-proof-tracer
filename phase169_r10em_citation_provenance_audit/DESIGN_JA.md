# Phase 169 R10EM — 引用の由来追跡の設計監査

## 監査目的

R10EL は表示上の非表示判定を共通化した。一方、R10A は生成元像全体の引用集合が空でないことを要求し、R10EC は各生成元像の祖先に引用付き GIVEN があることを要求している。R10EM はこの差を実際の検証済み Proof Tree から監査する。

## 対象

`pi_28^22`（6-stem・14回）、`pi_32^22`（10-stem・10回）、`pi_23^15`（8-stem・5回）、`pi_33^24`（9-stem・13回）。R10EK/R10EL の表示抑制数 31、40、10、110 を保持する。

## 安全境界

ProofStep のオブジェクト同一性とその `premises` だけをたどる。`ProofRule.GIVEN` である実ステップの `step_citation_numbers` と `model.citations` を照合する。数式表記、CSV の生成元名、文献ラベルから GIVEN や推論を新規作成しない。欠落した祖先、未登録 Citation、表示用引用との不一致は失敗とする。

監査専用なので、本番 Renderer、既存 Projection、命題台帳、テスト、文書は変更しない。部分証明を完成証明に昇格させない。全体 pytest は Phase 169 の終了時まで実施しない。

## 次の工程との境界

R10EM で各生成元像の引用付き GIVEN を検証できても、R10A の全入力について従来より強い条件への変更が互換であるとは限らない。次の実装では、呼び出し側の旧契約を保つパラメータ化を検討する。数式組み立ての一本化は、それとは別の責務として扱う。
