# Phase 171 R20R1 — 既存 R20 パッチ適用後の経路監査

## 判明した問題

R20 は限定 pytest 15件のうち13件が PASS、2件が FAIL で、右端群と位数4の完成条件を満たしていない。

既存の `phase165_r6_2_r4_r8_dedup.py` は同じ引用元の η 専用特殊化と汎用特殊化をすでに厳格に重複排除する。Phase 169 R3X では Proposition 5.1 による直接特殊化と安定輸送が別々の正当な経路として報告された。R19 の `found 2` は単純な同一引用元の規則重複だけとは断定できない。

既存ファイル、既存クラス、既存関数の変更は**なし**。R20 に適用された既存の未コミット変更は保持する。

## 監査の方法

1. Git にコミット済みの共通 Provider が既知の R19 ベースラインであることと、ローカルが R20 の適用後の全文と一致することをチェックする。
2. R19 の観測結果 `RIGHT_GROUP_AMBIGUOUS_DERIVATIONS` を確認する。
3. 実際の Public Context と R2I Screened Context から、位数計算の右端群の正確な Goal を得る。
4. 右端群の各 `GoalExpansion` を1件ずつ元の再帰探索器で解決する。子 Goal の Provider は元の共有 Provider を用いる。
5. `proved` の場合は実 ProofStep と登録済み先行出典の GIVEN 祖先を検証する。
6. `output/audit.json` と端末に各候補の結果を出力する。

## 守るべき境界

- 新しい `GIVEN` を追加しない。
- 完成済み証明木を投入しない。
- 任意の二つの数学的証明経路を同一視しない。
- 正しい安定輸送経路を暗黙に削除しない。
- 既存 API、Trust Boundary、共通 Resolver を変更しない。
- 全体 pytest は Phase 終了時のみ。

## 完了条件と次の境界

R20 の差分を変更せず、個別の右端群候補について `proved` / `unresolved` と対応する引用出典を観測できること。R20R2 ではその監査結果を踏まえ、`SourceBoundGoal` を用いた出典限定の下位目標が妥当か評価する。本監査だけでは R20 の失敗を修正したとは見なさない。
