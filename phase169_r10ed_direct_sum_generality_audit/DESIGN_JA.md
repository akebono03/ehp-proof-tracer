# Phase 169 R10ED — 直和群 Narrative Projection の一般性監査

## 目的

Phase 169 R10EC は、完全な Proof Tree と引用に基づく直和群の懸垂像を、1回ずつの等式ではなく $E^r$ の終点対応として表示する。

R10ED は実装追加ではなく、その圧縮が 9-stem 固有の例外処理でないこと、および証拠不足のときに表示圧縮を拒否することを確認する。Proof Tree、検索規則、文献、群構造の事実は変更しない。

## 変更対象

新規 `phase169_r10ed_direct_sum_generality_audit/` 配下の `__init__.py`、`profile.py`、`adversarial.py`、`audit.py`、2つの限定テスト、`run.ps1`、この文書、`README.md`。既存のクラス・関数・import は変更しない。

## 実例監査

- $(n,k)=(13,9)$：$r=2$、3成分
- $(n,k)=(15,8)$：$r=5$、2成分
- $(n,k)=(15,9)$：$r=4$、3成分
- $(n,k)=(24,9)$：$r=13$、3成分
- $(n,k)=(30,9)$：$r=19$、3成分

各例を登録済み Goal から探索し、同一の screened bridge（出典順序で選別された命題接続）で Trust Boundary の再検証を行う。Projection の $r$、直和成分数、生成元像の個数、本文の集約等式、引用、非表示ステップの規則種別、Proof Tree の不変性、重複表示を検査する。

## 拒否監査

検証済みモデルのコピーをテスト専用に改変し、次の場合に `project_verified_direct_sum_transport` が `None` を返すことを検査する。

1. Root の欠落
2. 表示順序の重複
3. 生成元像が表示順序から欠落
4. Root が要求する生成元像の欠落
5. 生成元像の順序入れ替え
6. 全引用の欠落
7. 登録されていない引用番号への改変
8. 中間生成元像への独立した引用
9. 別の証明ステップからの中間像の参照

これらの改変モデルは正当な証明ではなく、**必ず public Web の Trust Boundary を通すべきものではない**。`rejection_checks()` の内部だけで拒否を確認する。

## 完了条件

限定 pytest と5群の監査が成功し、全群 `complete`・Trust Boundary PASS・重複0・予期しない本番変更なし、かつ9種類の改変モデルがすべて拒否されること。

## 対象外と次段階

別 stem すべてへの網羅的対応、$r=1$ の圧縮、1成分の巡回群への直和用圧縮、追加の数学的命題登録は今回行わない。全体 pytest は Phase 169 終了時のみ実施する。
